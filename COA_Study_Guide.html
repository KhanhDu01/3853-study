The 60-second mental model (read this before anything else)

A computer does only four kinds of things: process data, store data, move data, and control itself. Everything in this course is a detail of one of those four.

  • The hardware: a processor (CPU) + main memory + input/output + something connecting them (buses). The CPU itself is a control unit + an ALU + registers.
  • The software: a program is a list of instructions. Each instruction is executed in an instruction cycle: fetch it, decode it, execute it.
  • Under the hood, each instruction is a short sequence of micro-operations ("copy PC to MAR", "add 1 to PC"). The control unit is the thing that turns an instruction into those micro-operations, at the right times, by switching control signals on and off.
  • The data: everything is bits. Numbers can be written in any base (binary is what the hardware uses, hex is what humans read, BCD is a compromise). Negative numbers are usually two's complement. Fractions are either fixed point or floating point (sign + biased exponent + fraction).
  • The storage hierarchy (registers → cache → main memory → disk → tape) exists because fast memory is expensive. Disks are mechanical, which is why their performance is described with seek, rotation, and transfer times — and why RAID exists (to trade capacity/cost for speed and/or reliability).

If you can retell that paragraph, you already understand the shape of the course.

Chapter 1 — Basic Concepts and Computer Evolution

The big idea in one paragraph

A computer is not one clever thing; it is a hierarchy of simple things. At the top you see a program; underneath, the machine is four big blocks (processor, memory, I/O, interconnection), each built from smaller blocks, down to gates and transistors. Two words organise the whole chapter: architecture (what the programmer can see) and organization (how it is actually built). The rest of the chapter is history: how we got from room-sized vacuum-tube machines to a chip with billions of transistors — a story summarised by Moore's Law.

Architecture vs organization (a favourite exam distinction)

ArchitectureOrganization
What it isThe attributes visible to the programmerThe operational units and their interconnections that realise those attributes
ExamplesInstruction set, how many bits represent each data type, I/O mechanisms, memory-addressing techniquesControl signals, the interfaces between computer and peripherals, the memory technology used
Why it mattersIt directly affects the logical execution of a program — two machines with the same architecture run the same binariesIt is transparent to the programmer — it affects speed and cost, not what the program can do

Analogy: the architecture of a house is "three bedrooms, one bathroom, front door facing north". The organization is "brick walls, gas heating, copper pipes". You can rebuild the house in concrete with underfloor heating (different organization) and it is still the same house plan (same architecture). That is exactly what IBM did with System/370 (1970): many models with different speeds and prices, one architecture, so a customer could buy a faster model without abandoning their software. New models used new technology but kept the architecture — which is why that architecture survived for decades in IBM's mainframes.

Why this matters in practice: architecture is a contract with software. Organization is where engineers compete on speed and price without breaking the contract.

Structure and function

  • Structure = how components relate to each other (the wiring diagram).
  • Function = what each component does (the job description).
  • A complex system is hierarchical: made of subsystems, each made of sub-subsystems. Hierarchy is essential because it lets a designer work at one level at a time — you don't think about transistors while designing a cache.

The four basic functions

Every computer, from a watch to a supercomputer, does exactly these four things:

  1. Data processing — doing arithmetic and logic on data. Data comes in many forms and the processing requirements are broad.
  2. Data storage — short-term (registers, cache, main memory) and long-term (disk, tape, flash).
  3. Data movement — moving data in and out. When the other end is a directly connected peripheral, we call it I/O; when it is over a longer distance to a remote device, we call it data communications.
  4. Control — a control unit manages the computer's resources and orchestrates the other three functions in response to instructions.

Example: you type a letter. Keys → I/O (movement) → characters stored in memory (storage) → spell-check and formatting (processing) → all sequenced by the control unit (control) → screen and disk (movement again). Every computer does these four, always.

The four structural components (prep-work question)

This is the exact answer expected:

  1. Central processing unit (CPU) — controls the operation of the computer and performs its data processing functions. Often called simply the processor.
  2. Main memory — stores data.
  3. I/O — moves data between the computer and its external environment.
  4. System interconnection — some mechanism that provides communication among the CPU, main memory, and I/O. The classic example is the system bus: a set of conducting wires to which all the other components attach.

Inside the CPU there is a second, smaller version of the same table:

CPU componentJob
Control unitControls the operation of the CPU (and hence the computer)
ALU (arithmetic and logic unit)Performs the computer's data-processing function
RegistersProvide storage internal to the CPU
CPU interconnectionCommunication among the control unit, ALU, and registers

Analogy: the CPU is a kitchen. The ALU is the chef (does the work), the registers are the counter space right next to the chef (fast but tiny), the control unit is the head chef reading the orders and calling out steps, and the CPU interconnection is the kitchen's internal layout that lets them pass things. Main memory is the pantry down the hall; cache is a shelf between the pantry and the counter.

Cache and the memory hierarchy

Main memory is large but comparatively slow; the processor is fast. Cache is a small, fast memory between the processor and main memory that holds data the processor is likely to need soon.

  • L1 is closest to the core and fastest/smallest; L2 and L3 are further away, larger and slower.
  • The point of the hierarchy is that most accesses hit the small fast level, so the average access time approaches the fast memory's while the capacity approaches the large memory's.

You will meet this again in Chapter 3 (memory hierarchy) and Chapter 4 (cache design).

Core, processor, chip — get the words right

  • A core is one processing unit on a chip. It may be equivalent to a whole CPU on an older single-CPU machine.
  • A processor is the piece of silicon containing one or more cores; it interprets and executes instructions.
  • A multicore processor has several cores on one chip.
  • On a single-core system, "CPU" and "processor" mean the same thing. On a multicore chip, they don't — that's why the modern term is core.

Moore's Law (prep-work question)

The expected answer: In 1965, Gordon Moore (co-founder of Intel) observed that the number of transistors that could be put on a single chip was doubling every year, and he correctly predicted that this pace would continue into the near future.

Two refinements worth knowing:

  • The pace was later revised (in the 1970s) to a doubling roughly every 18 months to two years, and that is the version the industry ran with for decades.
  • It is an observation plus an industry roadmap, not a law of physics. It held because the industry decided to hold it — each generation funded the next factory.

Why it mattered so much (the consequences are the interesting part):

  • Cost fell for both logic and memory — the same function got cheaper every year.
  • Speed rose: shorter electrical paths mean signals take less time to cross the chip.
  • Computers got smaller, so they could go into more environments (phones, cars, implants).
  • Power and cooling needs fell per function.
  • Fewer inter-chip connections were needed, which improved reliability.

The modern coda: the doubling has slowed, and the constraint is now power (you can't cool a chip that keeps doubling its power) rather than transistor size. That is why the industry went multicore — when you can't make one core faster, you put several on a chip. That single sentence connects Moore's Law to the multicore machines in the slides.

The evolution in five stages (know the shape, not the dates)

  1. Vacuum tubes (1940s–50s). Logic and memory were tubes; machines were huge, hot, and unreliable. The IAS computer (Princeton, completed 1952) established the stored-program concept — the idea, associated with John von Neumann, that instructions live in the same memory as data. That is the conceptual breakthrough of the era: the program is data.
  2. Transistors (late 1950s). A transistor is a solid-state switch: a small voltage on the gate makes it conduct or stop conducting. Smaller, cooler, far more reliable than a tube.
  3. Integrated circuits (1960s). Many transistors fabricated together on one chip of silicon, then wired by metallization. The IBM System/360 (April 1964) made the architecture/organization split famous.
  4. Microprocessors (1970s). The whole CPU on one chip. The Intel 4004 (1971) was the first; the 8080 was the first general-purpose microprocessor and powered the first PCs; the 8086/8088 created the x86 line (the 8088 went into IBM's first PC).
  5. Multicore and embedded (2000s–now). Billions of transistors per chip, several cores, and processors everywhere: phones, cars, sensors. ARM (from Acorn RISC Machine, now Advanced RISC Machine) became the most widely used processor architecture in the world precisely because it is small, fast, and low-power.

Trend to remember rather than the table: each generation traded size, cost, heat, and unreliability for density and speed. The Intel table in the slides is just that trend written out: 2,300 transistors (4004, 1971) → 7.2 billion (Core i9, 2017).

The IAS machine (only because of Exercise 1)

The IAS is the first stored-program computer design, and its register set explains how every later processor works:

RegisterHolds
MBR (memory buffer register)The word being sent to/from memory or I/O
MAR (memory address register)The address of the word in the MBR
IR (instruction register)The 8-bit opcode being executed
IBR (instruction buffer register)The right-hand instruction of a memory word

The IAS memory word holds two 20-bit instructions or one 40-bit number — a nice illustration of the era's trade-offs. Programming it meant writing actual machine code (no assembler existed), which is why Exercise 1 says "the IAS did not have assembly language, only machine language".

Embedded systems, IoT, and ARM (context, low priority)

  • An embedded system is electronics + software inside a product that isn't a computer (a washing machine, a car's engine controller). There are billions of them per year.
  • They impose real-time constraints: the software must finish in time to match the physical world (a fuel injector can't be "a bit late").
  • Deeply embedded systems use a microcontroller, are often programmed once into ROM, and have no user interface. Extreme limits on memory, size, time, and power.
  • The Internet of Things is the fourth generation of computing: billions of small networked devices, most of them deeply embedded.
  • ARM dominates this space: RISC-based, high speed, small die, low power.

Traps and memory hooks

  • Architecture vs organization: architecture = visible to the programmer; organization = hidden implementation. If the question says "instruction set", it's architecture. If it says "control signals" or "memory technology", it's organization.
  • The four functions are processing, storage, movement, control. Don't confuse them with the four structural components (CPU, memory, I/O, interconnection) — one is what it does, the other is what it's made of.
  • Moore's Law is about transistor count per chip, not speed, and the original statement was "every year". Say "doubling every year (later ~18 months)" to be safe.
  • Hierarchy is the theme of the chapter: structure is hierarchical, the memory is hierarchical, and complexity is managed one level at a time.

If you remember only five things

  1. Architecture = programmer-visible; organization = how it's built.
  2. Four functions: data processing, data storage, data movement, control.
  3. Four structural components: CPU, main memory, I/O, system interconnection.
  4. Inside the CPU: control unit, ALU, registers, CPU interconnection.
  5. Moore's Law: transistors per chip doubling every year (1965), later ~18 months — the engine behind five generations of computers.

Chapter 3 — A Top-Level View of Computer Function and Interconnection

The big idea in one paragraph

A computer is a machine that repeats one loop forever: fetch an instruction, execute it. Everything else in this chapter supports that loop. Instructions and data live together in memory (the stored-program idea). The loop gets complicated in two ways: the outside world needs attention at unpredictable times (interrupts), and the pieces have to talk to each other (buses and, nowadays, point-to-point links). Understand the loop, the interrupt, and the bus, and you understand the chapter.

The stored-program idea (von Neumann)

The von Neumann architecture (from the IAS machine at Princeton) rests on three claims:

  1. Data and instructions live in the same read–write memory. No separate program memory.
  2. Everything is addressable by location, regardless of what type it is — the machine doesn't care whether address 940 holds a number or an instruction.
  3. Execution is sequential unless an instruction explicitly changes the flow (a jump).

Before this, a computer was hardwired: its logic was wired for one computation, and changing the problem meant rewiring (Figure 3.1a). The breakthrough was to build general-purpose arithmetic/logic hardware plus control signals, where each operation gets a unique code; a sequence of codes is software, one code is an instruction, the decoder is an instruction interpreter, and interpreter + arithmetic hardware = the CPU (Figure 3.1b).

Why it matters: a program becomes data you can store, copy, and load. That is the difference between a calculator and a computer.

The cast of registers

RegisterHolds
PC (program counter)Address of the next instruction
IR (instruction register)The instruction currently being executed
MAR (memory address register)Address for the next memory read/write
MBR (memory buffer register)Data just read from, or about to be written to, memory
I/OAR / I/OBRThe I/O equivalents: which device, and the data
AC (accumulator)A working register for arithmetic

The instruction cycle: fetch, then execute

  1. Fetch. The CPU puts the PC on the address bus (MAR ← PC), reads memory into the MBR, copies it to the IR, and increments the PC to point at the next instruction.
  2. Execute. The CPU decodes the IR and does whatever it says — load, add, store, jump.

The cycle repeats until the machine halts (power off, an unrecoverable error, or a halt instruction).

A concrete example (from the slides). Instructions are 16 bits: a 4-bit opcode (so 2⁴ = 16 possible operations) and a 12-bit address (so 2¹² = 4,096 = 4K words of memory). A tiny program adds two numbers:

AddressInstructionMeaning
3001940Load AC from memory 940
3015941Add memory 941 to AC
3022941Store AC into memory 941

Following the cycles:

  1. Fetch: PC = 300 → IR = 1940; PC becomes 301.
  2. Execute: opcode 1 = load; address 940 → AC gets the value at 940.
  3. Fetch: PC = 301 → IR = 5941; PC becomes 302.
  4. Execute: opcode 5 = add; AC ← AC + [941].
  5. Fetch: PC = 302 → IR = 2941; PC becomes 303.
  6. Execute: opcode 2 = store; [941] ← AC.

Three instruction cycles, six steps. Notice that the CPU never "knows" what the program is about — it just repeats fetch/decode/execute.

The four categories of instruction action (prep-work question)

This is exactly what the question asks: what general categories of functions are specified by computer instructions?

  1. Processor–memory: data may be transferred from processor to memory, or from memory to processor. (Loads and stores.)
  2. Processor–I/O: data may be transferred to or from a peripheral device, by transferring between the processor and an I/O module.
  3. Data processing: the processor may perform some arithmetic or logic operation on data (add, subtract, AND, shift…).
  4. Control: an instruction may specify that the sequence of execution be altered — a jump/branch.

Example of control: an instruction at address 149 says "jump to 182". The PC is set to 182, so the next fetch is from 182, not 150. Only a control instruction changes the PC. One instruction can combine categories (e.g., "add memory to register and set a flag").

The finer-grained cycle states

Real processors break the cycle into states, which is useful vocabulary:

  • iac — increment the address counter.
  • if — instruction fetch.
  • iod — instruction operation decoding (what operation, which operands).
  • oac — operand address calculation.
  • of — operand fetch.
  • do — data operation.
  • os — operand store.

The top row (fetch) involves the processor and memory/I-O; the lower states are internal to the processor. Note that oac can appear twice — once to work out where the first operand is and once for the second — and that a vector or string operation may repeat of/os many times.

Interrupts: why the loop needs an escape hatch

The processor is much faster than I/O devices. If the processor sends a character to a printer and then waits for the printer, it may idle for hundreds or thousands of instruction cycles. That's the motivation for interrupts (Figure 3.7).

Without interrupts: the user program's WRITE call starts an I/O program that prepares the data, issues the command, and then polls (repeatedly checks) until the device is done. The user program is blocked the whole time.

With interrupts: the I/O program prepares the data and issues the command, then returns control immediately. The device works concurrently. When it finishes, it raises an interrupt request; the processor suspends the user program, runs a small interrupt handler, and then resumes exactly where it left off. The user program never knows.

Sources of interrupts (Table 3.1):

ClassExamples
ProgramArithmetic overflow, division by zero, illegal instruction, reference outside allowed memory
TimerThe processor's own timer, used for regular OS functions
I/ONormal completion, a service request, error conditions
Hardware failurePower failure, memory parity error

The interrupt cycle

At the end of each execute phase, the processor tests for a pending interrupt:

  • None: go straight back to fetch.
  • Pending: save the context (at minimum the PC, plus whatever else the handler will clobber), then load the PC with the start address of the interrupt handler. The handler runs, works out the cause, deals with it, and returns — restoring the saved context so the original program continues.

The overhead of saving/restoring context is tiny compared with the I/O wait it eliminates. This is why interrupts are one of the most important ideas in computer architecture.

Two approaches to multiple interrupts (prep-work question)

This is the expected answer. When several devices can interrupt, you need a policy:

Approach 1 — disable interrupts while an interrupt is being processed. A disabled interrupt is one the processor can and will ignore. New requests stay pending and are checked after interrupts are re-enabled.

interrupt → disable → run handler → enable → check pending → resume

The result is strictly sequential handling: one handler runs to completion before the next. It is simple and correct, but it has a flaw: it ignores priority and time-critical needs. A slow printer handler could delay a communications line long enough to lose data (the incoming character is overwritten).

Approach 2 — define priorities, and allow a higher-priority interrupt to interrupt a lower-priority handler. Now a long, low-priority job can be preempted by an urgent one. This is nested interrupt handling, and it is what real systems do.

Worked timeline (the classic Figure 3.14 example). Priorities: printer = 2, disk = 4, communications = 5 (higher number = higher priority).

TimeEvent

Notice at t=25: the printer handler resumes, but only until it is safe to switch — the higher-priority disk is served before the printer does any more work. That is what "priority" means in practice.

Getting data in and out

  • Programmed I/O: the processor issues the command and waits/polls. Simple, but wastes processor time.
  • Interrupt-driven I/O: the processor issues the command and continues; the device interrupts when done. Much better, but every word still passes through the processor.
  • DMA (direct memory access): the processor grants the I/O module permission to read/write memory directly. The module transfers a whole block without the processor, and interrupts only when the block is done. This is how disks and network cards move bulk data.

Interconnection: how the pieces talk

An interconnection structure is the set of paths connecting the processor, memory, and I/O. Two families:

The bus

A bus is a shared pathway joining two or more devices. It is a shared medium: everyone hears the signal, so only one device may transmit at a time. A bus is a bundle of lines, each carrying one bit.

BusCarriesWidth matters because
Data busThe actual dataWidth = bits transferred at once. A 32-bit bus fetching a 64-bit instruction needs two memory accesses
Address busWhich location/deviceWidth = maximum addressable memory
Control busCommands and timingTells devices what to do and when it is valid

Control lines typically include memory read/write, I/O read/write, transfer acknowledge, bus request/grant, interrupt request/acknowledge, clock, and reset.

Two operations on a bus:

  • Send: obtain the bus, then put data + address on it.
  • Request: obtain the bus, then put the request on the control/address lines and wait for the response.

Buses are cheap and simple, but they have a ceiling: a wide, fast, shared bus is hard to keep synchronised, and every device shares the bandwidth. That is why high-performance systems moved to point-to-point links.

Point-to-point and QPI

QPI (QuickPath Interconnect), introduced by Intel in 2008, connects processors and I/O directly, with no shared bus and no arbitration. Its features:

  • Multiple direct connections: any node can reach any other through a switching fabric, and traffic can take different paths.
  • Layered protocol: physical, link, routing, and protocol layers — like a network, because that's what it is.
  • Packetised transfer: control headers plus error-control codes.

Some numbers worth recognising: a phit is the physical unit (20 bits), a flit is the link-layer unit (80 bits = 72-bit payload + 8-bit CRC), a QPI link has 20 data lanes + 1 clock lane per direction, and at 6.4 GT/s that gives 16 GB/s per direction, 32 GB/s total. Lanes are differential (LVDS): current goes out one wire and back the other, and the direction of the current is the bit.

PCIe is the I/O counterpart: a point-to-point fabric with a root complex, switches, and endpoints, organised in layers (physical, data link, transaction). It uses split transactions — a request is answered later by a completion packet with a unique ID — so the bus is never blocked waiting. It supports posted writes (no response needed), 32/64-bit addressing, and four address spaces: memory, I/O, configuration, and message.

Why point-to-point won: the electrical limits of a wide, fast, synchronous shared bus (timing skew, arbitration overhead) plus the arrival of multicore made a shared bus a bottleneck. Point-to-point gives lower latency, higher data rate, and scalability.

Traps and memory hooks

  • Fetch increments the PC; execute may change it. That's the whole distinction between sequential execution and branches.
  • Interrupt ≠ trap. Here, "interrupt" covers both external (I/O) and internal (program error) causes; the mechanism is the same.
  • Disabling interrupts does not lose them — they stay pending. It just delays them (which can be fatal for a fast device).
  • Priority is not the same as arrival order. A higher-priority request can overtake a lower one that arrived earlier.
  • Bus width vs bus speed: both raise throughput, but a wider data bus costs pins, and a faster bus costs signal integrity.
  • DMA is not interrupt-driven I/O: with DMA the data does not pass through the processor.

If you remember only five things

  1. Stored program: instructions and data share memory; fetch → execute forever.
  2. Four instruction-action categories: processor–memory, processor–I/O, data processing, control.
  3. An interrupt saves the context, runs a handler, and resumes — so the processor doesn't wait for slow devices.
  4. Multiple interrupts: disable (sequential) or prioritise (nested, preemptive).
  5. Buses have data/address/control lines and are shared; modern systems use point-to-point links (QPI, PCIe) instead.

Chapter 7 — External Memory (disks, RAID, optical, tape, SSDs)

The big idea in one paragraph

Main memory is fast, expensive, and loses everything when the power goes off. External memory is the opposite: cheap, huge, permanent — and slow, because a magnetic disk is a physical machine with a spinning platter and a moving arm. So this chapter is mostly about geometry: where the data physically sits, and how long it takes to get there (seek + rotation + transfer). Once you understand the geometry, RAID makes sense as the engineering answer to "disks are slow and they fail": spread data across several disks for speed, and store extra information for safety.

Anatomy of a magnetic disk

TermMeaningAnalogy
PlatterA circular disk with a non-magnetic substrate coated in magnetisable materialA stack of records
SurfaceOne side of a platter; data is recorded on itOne face of a record
HeadThe tiny electromagnet that reads/writes one surfaceThe needle
TrackOne concentric ring on a surfaceOne groove of the record
SectorA fixed-size slice of a track (the unit of transfer)One song on the groove

The platters are stacked, and one head per surface is mounted on a single arm — so all the heads move together and always sit over the same cylinder. That is why cylinder is a useful concept: you can read all the tracks at one radius without moving the arm, just by switching heads electronically.

  • Tracks are separated by intertrack gaps (tolerances for head misalignment and magnetic interference).
  • Sectors are separated by intersector gaps, which relax mechanical precision; most modern disks use fixed-length sectors.

Why glass substrates? (prep-work question)

The substrate is the base material; it used to be aluminium alloy, and now is often glass. The five advantages (this is the expected list):

  1. More uniform magnetic film surface → higher disk reliability.
  2. Far fewer surface defects → fewer read/write errors.
  3. Supports lower fly heights — the head can fly closer to the surface.
  4. Better stiffness → less disk dynamics (vibration/wobble).
  5. Greater ability to withstand shock and damage.

Why lower fly height is the big one: a narrower head can read narrower tracks, which means higher areal density (more bits per square centimetre). But a smaller head must fly closer to the surface to work — and the closer it flies, the more a single speck of dust or a bump matters. Glass gives you a smoother, stiffer, flatter surface, so you can fly lower safely. That is the chain: glass → smoother/flatter → lower fly height → narrower tracks → more capacity.

Read/write heads, briefly

  • Write: current pulses through a coil create a magnetic field across a tiny gap; the field magnetises a small area; reversing the current reverses the magnetisation.
  • Read (old): a moving magnetic field induces a current — the same structure could do both.
  • Read (modern): a separate magnetoresistive (MR) head, whose resistance depends on the magnetisation direction. That allows higher-frequency operation, hence greater density and speed.

  • 15,000 rpm → 250 rev/s → 4 ms per revolution → 2 ms average latency.

CAV vs MZR — why disk capacity is limited by the inner track

  • CAV (constant angular velocity): the disk spins at a fixed speed, so the outer tracks move faster under the head than the inner ones. If you keep bit spacing constant, you'd have to change the clock rate with radius.
  • With CAV, bits are spaced so that the innermost track works — which wastes the outer tracks (they could hold more). Capacity is capped by what fits on the inner track.
  • MZR (multiple zone recording): divide the surface into concentric zones (typically ~16). Within a zone, the number of bits per track is constant; outer zones hold more sectors. This raises capacity at the cost of more complex timing circuitry (the bit rate changes at zone boundaries).

Sector format and why block size grew

A legacy 512-byte sector records, in order: Gap (separates sectors), Sync (marks the start, aligns timing), Address mark (sector number/location and status), Data (512 B), ECC (error-correcting code).

Two problems with 512-byte sectors:

  1. Overhead is a big fraction. 65 bytes of control data on 512 bytes of payload gives efficiency 512/(512+65) ≈ 0.88 — about 12% of the disk is bookkeeping.
  2. Higher density makes defects worse. A single defect damages a larger fraction of the payload when the payload is small.

Advanced Format uses a 4,096-byte block: 15 bytes of leading overhead and 100 bytes of ECC gives 4096/(4096+115) ≈ 0.97 — almost 10% more usable capacity, plus the ability to correct longer error bursts.

RAID — the main event

RAID = Redundant Array of Independent Disks. The idea: use several cheap disks together so that the array is faster, bigger, and/or more reliable than one big expensive disk. Three shared traits:

  1. The OS sees one logical drive.
  2. Data is striped — consecutive strips are spread round-robin across the disks, so requests can be served in parallel.
  3. Redundant capacity stores parity (or a copy), so a failed disk can be reconstructed.

Stripe vs strip: a strip is a chunk of data placed on one disk; a stripe is the set of strips (one per disk) at the same position across the array. Striping alone gives speed and capacity but no redundancy — that is the trap in the prep question.

How is redundancy achieved in a striped RAID system? (prep-work question)

The expected answer: RAID 1 achieves redundancy by keeping two identical copies of all data (mirroring); the higher RAID levels achieve it by storing error-correcting codes (parity) in redundant capacity. More precisely:

Parity in one sentence: the XOR of all the data strips is stored as an extra strip; if one strip is lost, XOR-ing the survivors with the parity recovers it. (XOR is its own inverse — that's the magic.)

The levels in plain English

  • RAID 0 — speed, no safety. Maximum capacity and throughput, zero fault tolerance. One disk dies, everything is gone. Used for video editing and scratch space.
  • RAID 1 — mirroring. Every write goes to two disks. Reads can come from either copy (up to 2× read rate), writes have no penalty, and recovery is just "read the other copy". Cost: you buy twice the disks for the same capacity.
  • RAID 2 — Hamming code. All disks work together on every request (parallel access), with ECC across the bits. Very high transfer rates, but the redundancy overhead is high and it was never commercially successful.
  • RAID 3 — bit-interleaved parity. Like RAID 2 but with simple parity on one check disk. Excellent for large sequential transfers (video streaming), poor for many small requests, because all disks must move together.
  • RAID 4 — block-interleaved parity. Disks work independently, so small requests can be parallel. But every write must update the parity disk, and updating parity needs the old data strip and old parity strip: two reads + two writes — the write penalty. The single parity disk is also a bottleneck.
  • RAID 5 — distributed parity. Same as RAID 4 but the parity blocks are spread across all disks, removing the parity-disk bottleneck. The most versatile level; the standard choice for file and database servers.
  • RAID 6 — dual parity. Two independent parity blocks on different disks. Survives two simultaneous failures — at the cost of a bigger write penalty and more complex control.

The trade-off to remember: RAID buys availability (and sometimes speed) with capacity and write performance. RAID 5 needs one extra disk; RAID 6 needs two; RAID 1 needs a full duplicate. Mirroring is simple and fast for writes; parity is cheap in capacity but slow for writes.

Solid-state drives (SSDs)

An SSD is semiconductor memory with no moving parts — it uses NAND flash. Compared with a hard disk it has: much higher IOPS, no seek or rotational delay, shock resistance, lower power, no noise, and no mechanical wear. Hard disks still win on cost per bit and maximum capacity.

Two practical problems:

  1. Performance degrades as the drive fills. Data is written in ~4 KB pages, but flash is erased in ~512 KB blocks (~128 pages). Changing one page means: read the whole block, modify the page, erase the block, write it back. As the drive fragments, one small write touches many blocks. Fixes: over-provisioning, erasing free blocks in idle time, and TRIM (the OS tells the drive which blocks are no longer needed).
  2. Wear-out. A flash cell wears out after a finite number of erases (on the order of 100,000). Fixes: a write cache to batch writes, wear levelling (spread writes evenly), bad-block management, and RAID.

Optical memory (CD/DVD/Blu-ray)

  • Data is stored as pits pressed into a polycarbonate disk; the smooth areas between pits are lands. A laser reflects strongly off a land and scatters off a pit; a pit edge is read as 1, no change as 0.
  • CLV (constant linear velocity): one long spiral track from the centre outward, with equal-length sectors packed evenly. The drive changes rotation speed so the track moves past the laser at a constant rate. Random access is therefore slow (the drive must seek, change speed, read the address, fine-tune).
  • Why CD holds ~680 MB: the spiral is long, the pits are tiny, and sectors are uniform.
  • DVD got more capacity three ways: tighter packing (shorter-wavelength laser, smaller pit and track spacing), a second semi-reflective layer read by focus adjustment, and two-sided disks. 4.7 GB → 8.5 GB → 17 GB.
  • Blu-ray uses a blue-violet (405 nm) laser and puts the data layer closer to the laser, so the focus is tighter and pits can be smaller: 25 GB per layer versus HD DVD's 15 GB — which is why Blu-ray won.
  • Optical strengths: cheap mass replication, removable, archival. Weaknesses: read-only (for pressed disks) and slow access (up to ~half a second).

Magnetic tape

  • Same magnetic principles, but on a long flexible plastic tape in a cartridge. Bits are recorded in tracks running lengthwise; modern drives use serial recording and serpentine recording (write a full pass in one direction, reposition the heads, write back the other way).
  • Tape is a sequential-access device: to read record N you must pass records 1…N−1. Great for backup and archive, terrible for random access.
  • It remains the lowest cost per bit and the slowest member of the hierarchy. LTO (Linear Tape-Open) is the standard family; capacities have grown from 200 GB to tens of TB per cartridge.

Worked example — Exercise 7.1 (the extra-credit disk problem)

8 surfaces, 512 tracks/surface, 64 sectors/track, 1 kB/sector, average seek 8 ms, track-to-track 1.5 ms, 3,600 rpm. Successive tracks in a cylinder can be read without moving the heads. (a) Capacity. Count sectors, then multiply by sector size:

sectors = 8 surfaces × 512 tracks × 64 sectors = 262,144
capacity = 262,144 × 1 KB = 262,144 KB = 256 MB   (MiB: 268,435,456 bytes)

one revolution = 60 s ÷ 3,600 rpm = 16.667 ms
average rotational latency = 16.667 ÷ 2 = 8.333 ms

5 MB = 5 × 1,024 KB = 5,120 KB → 5,120 sectors
5,120 sectors ÷ 64 per track = 80 tracks
80 tracks ÷ 8 tracks per cylinder = 10 cylinders

  • Initial rotational wait: 8.333 ms (the disk is already spinning; naming sector 0 doesn't make the wait zero).
  • Reading 80 tracks: each track is one revolution → 80 × 16.667 ms = 1,333.3 ms.
  • Moving between cylinders: 10 cylinders means 9 moves → 9 × 1.5 = 13.5 ms.
  • Rotational waits after each move: after moving, the head may have missed sector 0, so allow half a revolution each time → 9 × 8.333 ≈ 75 ms.
  • Total: 8 + 8.333 + 1,333.3 + 13.5 + 75 ≈ 1,438 ms ≈ 1.44 s.

64 KB × 60 = 3,840 KB/s = 3.75 MB/s (3,932,160 bytes/s)

Traps and memory hooks

  • Average rotational latency is half a revolution, not a full one. (The file starting at sector 0 does not change this.)
  • The number of cylinder moves is (cylinders − 1). The initial seek is already counted separately.
  • RAID 0 is not redundant. If the question asks "how is redundancy achieved", RAID 0 is the distractor.
  • RAID 5 is RAID 4 with the parity spread out. That one change removes the bottleneck.
  • Bigger sector = more efficiency, because the overhead is fixed while the payload grows.
  • Seek = arm, rotation = spin, transfer = read. Three different physical motions; don't add them twice.

If you remember only five things

  1. Disk geometry: platters → surfaces → tracks → sectors, with cylinders across surfaces.
  2. tB = tS + tL + tT, and average rotational latency is half a revolution.
  3. Glass: smoother, fewer defects, lower fly height, stiffer, tougher → higher density.
  4. RAID: mirroring (1) or parity (3/4/5/6) on top of striping; 5 distributes parity, 6 keeps two parities.
  5. SSD beats disk on latency and shock, loses on cost per bit; tape is cheapest and slowest; optical is cheap to replicate and slow to access.

Chapter 10 — Number Systems (bases, conversions, BCD, hex)

The big idea in one paragraph

A number written as 4728 is not a picture — it is a recipe: four thousands + seven hundreds + two tens + eight ones. The "base" (radix) tells you what each position is worth. Decimal uses powers of 10 because we have ten fingers; the computer uses powers of 2 because a wire is either on or off. Hexadecimal is just a shorthand for binary so humans don't have to read long strings of 0s and 1s. BCD is a different compromise: store decimal digits in 4-bit chunks so that a decimal display never needs conversion. That's the whole chapter: same number, different recipes.

Positional notation — the one rule that explains everything

In a base-r system, the digit in position i is multiplied by rⁱ. Position 0 is just left of the radix point; positions to the right get negative powers.

    4   7   2   8 . 2   5   6
   10³ 10² 10¹ 10⁰  10⁻¹ 10⁻² 10⁻³

So 4728 = 4×10³ + 7×10² + 2×10¹ + 8×10⁰ and 0.256 = 2×10⁻¹ + 5×10⁻² + 6×10⁻³.

  • Most significant digit (MSD) = leftmost, worth the most. Least significant digit (LSD) = rightmost.
  • The digit values must stay below the base — that's why base 10 has digits 0–9 and base 2 has only 0–1. Nine is the largest a decimal position can hold before it "carries over" into the next position. (A useful sanity check: the 0 in 509 doesn't mean "no tens" — 509 contains 50 tens plus 9 leftover. Each position stores only the leftover that can't be lumped into a higher position.)
  • In base 7, digits are 0–6 and the weights are …, 2401, 343, 49, 7, 1, 1/7.

Binary in one minute

Weights are 1, 2, 4, 8, 16, 32, … and, right of the point, 1/2, 1/4, 1/8, …

1001.101₂ = 8 + 1 + 0.5 + 0.125 = 9.625₁₀

Read it as: 1×2³ + 0×2² + 0×2¹ + 1×2⁰ + 1×2⁻¹ + 0×2⁻² + 1×2⁻³.

Binary → decimal: multiply each bit by its weight and add. Nothing more. Decimal → binary: the integer part and the fraction part are converted separately, and this is where people lose marks.

Decimal integers → binary: divide by 2, read the remainders upward

Convert 20:

20 ÷ 2 = 10 remainder 0   ← least significant bit (write last)
10 ÷ 2 =  5 remainder 0
 5 ÷ 2 =  2 remainder 1
 2 ÷ 2 =  1 remainder 0
 1 ÷ 2 =  0 remainder 1   ← most significant bit (write first)

Read bottom to top: 10100₂. Check: 16 + 4 = 20. ✔

Rule to remember: keep dividing; the remainders, read from the last one produced back to the first, are the binary digits. (Equivalently: the first remainder is the LSB.)

Decimal fractions → binary: multiply by 2, read the carries downward

Convert 0.625:

0.625 × 2 = 1.25  → integer part 1   ← first bit after the point
0.250 × 2 = 0.50  → integer part 0
0.500 × 2 = 1.00  → integer part 1   ← last bit

Read top to bottom: 0.101₂ = 0.5 + 0.125 = 0.625 ✔

Unlike integers, this may never terminate: 0.1₁₀ in binary is 0.0001100110011… repeating forever. That's why floating point has rounding — a finite decimal fraction often has no finite binary expansion. The deck's caveat: stop after the number of steps your required accuracy demands.

A warning about bases with digits above 9

Base 5 uses only 0–4. Twenty in base 5:

20 ÷ 5 = 4 remainder 0
 4 ÷ 5 = 0 remainder 4

Read up: 40₅ (4 fives + 0 ones = 20 ✔). If you ever write a "digit" of 5 or more in base 5, you've made an error.

Why assembly listings use hex (prep-work question)

The expected answer has three parts, and the fourth part from the answer key is the one students forget:

  1. It is more compact than binary. One hex digit replaces four bits, so a 32-bit instruction is 8 characters instead of 32.
  2. Data widths are multiples of 4 bits. A byte is 8 bits, a word is 16/32/64 — always a whole number of nibbles, so hex never leaves a ragged edge.
  3. Conversion is trivial. Grouping in fours is a visual operation; no division, no arithmetic, no loss of precision.
  4. The width is fixed, which keeps listings aligned. 3₁₀ is 03₁₆ and 128₁₀ is 80₁₆ — both two digits, so a column of hex values lines up. In decimal they'd be 1 and 3 characters wide, so the listing looks ragged to a human and is harder for a simple compiler to parse.

The deepest reason: hex is a notation for a bit pattern, not just for a number. It can describe an instruction, a character, or a pixel just as well as an integer. Binary is the machine's language; hex is a human-readable font for it.

BCD — Binary-Coded Decimal (prep-work question)

Definition (the expected answer): BCD is a way of representing decimal numbers in which each decimal digit is encoded into its own 4-bit binary number.

Example: 1278₁₀ becomes

1     2     7     8
0001  0010  0111  1000

So the BCD string is 0001 0010 0111 1000. Note what this is not: it is not 1278 in binary (which would be 0100 1111 1110). BCD stores the digits, not the value.

Two flavours

  • Packed BCD — two decimal digits per byte, as above. This is what the answer key describes.
  • Unpacked BCD — one digit per byte (usually the low nibble), the upper nibble being 0. Easier for character-oriented display hardware.

Why bother? Because a decimal display, a calculator keypad, or a financial system thinks in decimal digits. With BCD you never have to convert to binary and back, so 0.10 never becomes 0.0999999. Early calculators and cash registers did their arithmetic this way.

What it costs:

  • Only 10 of the 16 codes are legal. 1010–1111 are invalid BCD codes, so 6/16 of the code space is wasted — about 37% more storage than true binary.
  • Arithmetic needs correction. Normal binary addition gives the right answer only while a nibble stays ≤ 9; when it exceeds 9 (or produces a carry out), you must add 6 to skip over the six invalid codes.
    0010 1001   (29)
  + 0001 1000   (18)
  -----------
    0100 0001   ← low nibble 1001+1000 = 1 0001, which is invalid
    add 0110 to the low nibble:
    0100 0111   = 47 ✔
  • It is not a good format for general computation: an entire ALU would need BCD-aware adders.

One-line comparison: binary is how the machine computes; BCD is how a decimal machine displays; hex is how a human reads the bits.

  • Position 0 is the units position, and it is the last digit written, not the first. Off-by-one in the exponent is the single most common conversion error.

  4. Hex = 4 bits per digit; it is compact, aligned, trivially convertible, and fixed-width — which is why assembly uses it.

Chapter 11 — Computer Arithmetic (integers and floating point)

The big idea in one paragraph

The ALU only knows how to add and do logic on fixed-width patterns of bits. It has no minus sign, no decimal point, and no concept of "big". So everything else — negative numbers, subtraction, fractions, very large and very small values — has to be encoded into those bits by a convention that both the hardware and the programmer agree on. Two's complement makes subtraction "just addition". Floating point makes range and precision tradeable. Every formula in this chapter is a consequence of those two conventions.

The ALU in one line

The arithmetic and logic unit is the part that actually computes. Everything else in the computer exists to feed it operands and carry results away. It takes two operands from registers, produces a result into a register, and sets flags — the most important being overflow ("the result didn't fit").

Integers: three conventions

Two's complement is the one you must internalise. The trick is to stop reading the MSB as "sign" and start reading it as a weight of −2ⁿ⁻¹.

The "value box" (Figure 11.2): label the bit positions from the right with 1, 2, 4, 8, … and make the leftmost weight negative:

   -128  64  32  16   8   4   2   1      (8-bit two's complement)

Then 10000000 = −128, 11111111 = −128+64+32+16+8+4+2+1 = −1, and 01111111 = 127. Nothing is special-cased; you just add the weights. This one mental model replaces all the "flip the bits and add one" rules — use it to check them.

Three rules fall out of the box:

  • Negation: complement every bit (including the sign bit), then add 1. +18 = 00010010 → complement 11101101 → +1 → 11101110 = −18. Negating again returns +18.
  • Special cases: negating 0 gives 0 (the carry out is discarded), and negating −128 gives −128 — the one value whose negation is itself, because +128 doesn't exist in 8 bits.
  • Range: −2ⁿ⁻¹ … +2ⁿ⁻¹−1, asymmetric by exactly one. 8 bits: −128…127.

Sign extension (prep-work question)

Rule: to widen a two's complement number, copy the sign bit into every new position on the left. Positive numbers get leading 0s; negative numbers get leading 1s.

+18 as  8 bits: 0001 0010
+18 as 16 bits: 0000 0000 0001 0010     (pad with 0s)

-18 as  8 bits: 1110 1110
-18 as 16 bits: 1111 1111 1110 1110     (pad with 1s)

Why it must be the sign bit, not zeros: the old sign bit had weight −2⁷; in 16 bits the new sign bit has weight −2¹⁵. If you fill the new bits with 0, you lose the −2⁷ contribution and get a large positive number. If you fill with 1s, the new leading ones contribute −2¹⁵ + 2¹⁴ + … + 2⁷ = −2⁷ — exactly the weight you took away. The value is preserved.

Contrast: sign-magnitude only needs the sign moved to the new MSB and zeros elsewhere; one's complement needs a similar fill. This difference is a favourite exam question.

Addition, subtraction, overflow

  • Addition: just add the bit patterns; a carry out of the leftmost bit is discarded. The sign comes out right automatically.
  • Subtraction: A − B = A + (−B) = add A to the two's complement of B. This is why two's complement won: one adder plus a complementer does both operations.
  • Overflow rule: when adding two numbers with the same sign, overflow occurs iff the result has the opposite sign. Adding a positive and a negative can never overflow.
  • Overflow is not the same as carry. A carry out of the MSB is normal in unsigned arithmetic; overflow is the signed interpretation breaking.
  0101 (+5)        0110 (+6)        1001 (-7)
+ 0011 (+3)      + 0101 (+5)      + 1011 (-5)
---------        ---------        ---------
  1000 (-8) ✗      1011 (-5) ✗      0100 (+4) ✗
  wrong: +8        wrong: +11      wrong: -12

The first two have a carry into the MSB but not out of it; the third has the reverse. Either mismatch is the overflow condition in hardware.

Multiplication and division (the ideas, not the bit-shuffling)

Unsigned multiply is exactly school long multiplication in binary: for each multiplier bit, write the multiplicand (if the bit is 1) or zero (if 0), shifted left one place per step, and add. An n-bit × n-bit product needs 2n bits, so A (accumulator) and Q (multiplier) are concatenated to hold it. Hardware repeats n times: if the multiplier's low bit is 1, add the multiplicand; then shift the whole A–Q pair right.

  • Booth's algorithm exists because the straightforward version mishandles negative numbers (partial products of a negative multiplicand must be sign-extended, which breaks the simple add-shift). Booth recodes the multiplier by looking at the current bit and the bit to its right (Q0, Q−1): 00 or 11 → just shift; 01 → add; 10 → subtract. It naturally handles signed operands, and it is faster because a run of 1s becomes one add and one subtract instead of one add per bit.
  • Division: the hardware shifts the dividend left into a running remainder, subtracts the divisor, and if the subtraction "goes" it puts a 1 in the quotient bit; otherwise it restores the remainder and puts a 0. (That's restoring division.) For signed values the practical trick is: divide the magnitudes, then fix the signs — quotient sign = sign(dividend) XOR sign(divisor); remainder sign = sign(dividend).

Floating point: the real problem

Fixed point can represent integers and scaled fractions, but it cannot represent both 10⁻²⁰ and 10²⁰ with useful precision — you'd need an enormous word. Scientific notation solves it: keep a sign, a significand (the digits), and an exponent (where the point is).

976,000,000,000,000  =  9.76 × 10¹⁴
0.0000000000000976   =  9.76 × 10⁻¹⁴

Same digits, different exponent. The computer does this in base 2.

The IEEE 754 single-precision format (32 bits):

 S | EEEEEEEE | FFFFFFFFFFFFFFFFFFFFFFF
 1 |    8     |           23
  • S — sign: 0 = positive, 1 = negative.
  • E — biased exponent: the true exponent plus 127. Storing it biased means an 8-bit unsigned field can hold negative exponents (down to −126) and, crucially, larger exponents compare as larger integers.
  • F — the fraction, 23 bits. In a normalised number the leading 1 is implicit, so the significand is 1.F.

The formula (memorise this one):

value = (−1)^S × 1.F × 2^(E − 127)

Normalisation means "shift until exactly one 1 sits left of the point". 110.1 normalises to 1.101 × 2². Because that leading 1 is always there, it doesn't need storing — that's a free extra bit of precision (24 significant bits from 23 stored).

Decoding the three numbers from Exercise 11.2

(a) 1 10000011 11000000000000000000000

  1. S = 1 → negative.
  2. E = 10000011₂ = 128 + 2 + 1 = 131 → true exponent = 131 − 127 = 4.

  1. S = 0 → positive.
  2. E = 128 → exponent = 1.

Double precision is the same idea with a 1-bit sign, 11-bit exponent (bias 1023), and 52-bit fraction: value = (−1)^S × 1.F × 2^(E−1023).

The exponent field's two extreme values are reserved. This table is worth memorising:

  • Infinity is the correct answer to overflow (2¹²⁰ × 2¹⁰⁰ = 2²²⁰, too big) and to division by zero.
  • NaN is produced by undefined operations: 0/0, ∞/∞, 0×∞, ∞−∞, √(negative). NaN propagates: any operation with a NaN operand yields NaN, which is how an error quietly travels to the end of a calculation instead of crashing it.

Floating-point arithmetic: align, add, normalise, round

Adding X = 0.3×10² (30) and Y = 0.2×10³ (200):

  1. Align the exponents — shift the smaller operand right until the exponents match. 0.3×10² = 0.03×10³.
  2. Add the significands — 0.03 + 0.2 = 0.23.
  3. Normalise — here 0.23×10³ is already normal; in general shift left until one nonzero digit leads, decrementing the exponent.
  4. Round the result back to the format's precision.

Multiplication is easier: add the exponents (then subtract the bias once, because you added two biased values), multiply the significands, normalise, round. Division: subtract exponents (then add the bias back).

Four things that can go wrong: exponent overflow (too big → ±∞), exponent underflow (too small → often 0), significand underflow (bits shifted off the right during alignment — needs rounding), and significand overflow (a carry out of the top after adding — fix by shifting right and incrementing the exponent).

Guard bits (prep-work question)

Answer: guard bits are extra bits at the right end of the significand register, kept so that low-order bits are not lost when an operand is shifted during alignment; they let the final result be rounded correctly instead of being truncated early.

They matter most when you subtract two nearly equal numbers, because alignment can shift the smaller operand right past the end of the register.

A 4-bit-significand example (1 implicit bit + 3 stored), computing 8 − 7.5:

x = 1.000 × 2³           (8)
y = 1.111 × 2²  → 0.1111 × 2³   (7.5, shifted right one place)

Without a guard bit the register can only hold 0.111:
  8.000
- 7.000   ← the last 1 was shifted out!
-------
  1.000          answer: 1.0, but the true answer is 0.5

With a guard bit, 0.1111 survives:
  1.0000
- 0.1111
-------
  0.0001 × 2³ = 0.5   → normalise → 1.000 × 2⁻¹   ✔

The error was a factor of 2. With radix-16 formats the same effect can be a factor of 16, which is why guard bits are not optional.

Rounding and precision

When the exact result needs more bits than the format allows, you must round. IEEE 754 defines four modes:

  • Round to nearest (default): nearest representable value; exact halfway cases go to the value whose last bit is even ("round to even"). This avoids the systematic upward bias you'd get from always rounding half up.
  • Round toward +∞ (up), round toward −∞ (down), round toward 0 (truncate).

Truncation (toward 0) is the simplest and the worst: it always reduces the magnitude, so errors accumulate in one direction over a long computation. Interval arithmetic is the opposite philosophy — compute both a lower and an upper bound, and the width of the interval tells you how much to trust the answer; it relies on the directed roundings.

Traps and memory hooks

  • The exponent is biased, not signed. E = 131 means exponent 4, not 131.
  • A negative exponent is not a negative number. The sign bit alone controls the sign. 0.8125 has exponent −1 and is positive.
  • Don't forget the implicit 1. 1.F — writing .F gives results 2× too small.
  • Overflow ≠ carry. Overflow is about the signed range; carry is about the unsigned word.
  • Sign extension copies the sign bit; sign-magnitude pads with zeros. Mixing these up is the classic sign-extension error.
  • Guard bits protect the low end; the bias protects the high end. Two different problems, two different mechanisms.
  • Number-line picture for two's complement: values sit on a circle; adding moves clockwise, subtracting anticlockwise, and crossing the join (between +max and −max) is overflow.

If you remember only five things

  1. Two's complement: the MSB has weight −2ⁿ⁻¹. Everything else follows.
  2. Sign extension: replicate the sign bit into all new positions.
  3. value = (−1)^S × 1.F × 2^(E−127) — bias 127, implicit 1, 23 stored fraction bits.
  4. Align → add → normalise → round, and keep guard bits so alignment doesn't destroy the low bits.
  5. Overflow rule: same-sign operands, opposite-sign result.

Chapter 12 — Digital Logic (gates, combinational and sequential circuits)

The big idea in one paragraph

Everything digital is built from gates — tiny switches that compute AND, OR, and NOT. A circuit made only of gates, whose output depends only on the present input, is combinational: it can add, select, decode, but it cannot remember. Add feedback so the output depends on the past as well, and you get sequential logic: flip-flops, registers, counters — the things that make memory and processors possible. That's the whole chapter: gates → combinational → sequential → programmable devices.

Boolean algebra: the maths of 0 and 1

George Boole proposed it in 1854 as mathematics; Claude Shannon showed in 1938 that it describes relay switching circuits, and it became the design language of digital electronics.

  • Variables take 1 (true) or 0 (false).
  • AND (A·B, also written AB) is 1 only if both inputs are 1.
  • OR (A+B) is 1 if either or both are 1.
  • NOT (Ā) inverts.
  • Without parentheses, AND binds tighter than OR.
A BA·BA+BA NAND BA NOR BA XOR B
0 000110
0 101101
1 001101
1 111000
  • NAND = NOT AND; NOR = NOT OR; XOR = 1 when the inputs differ ("exactly one is 1").
  • For more than two inputs: AND = all 1s; OR = any 1; NAND = any 0; NOR = all 0s; XOR = an odd number of 1s.

The identities you actually use

A·1 = A          A+0 = A
A·0 = 0          A+1 = 1
A·A = A          A+A = A
A·Ā = 0          A+Ā = 1
A·(B+C) = AB+AC  A+(BC) = (A+B)(A+C)      ← the second one only works in Boolean algebra!

DeMorgan's theorem — the most useful tool for simplifying circuits:

(A·B)‾ = Ā + B̄        "NAND = OR of the complements"
(A+B)‾ = Ā · B̄        "NOR  = AND of the complements"

Example: simplify (A + B)(A + C). Expand: AA + AC + BA + BC = A + AC + AB + BC = A(1 + C + B) + BC = A + BC. Check with A=0: LHS = B·C, RHS = BC ✔.

Gates and functional completeness

A gate implements one Boolean operation. Symbols are standardised by IEEE Std 91; an inversion is shown by a small circle on the output. Gates have a small propagation delay ("gate delay"), and a signal is asserted when it goes to its true state.

Functionally complete sets can build any Boolean function:

{AND, OR, NOT}   {AND, NOT}   {OR, NOT}   {NAND}   {NOR}

That last pair is why real chips are often built from NAND only or NOR only: one gate type simplifies manufacturing. (You can build NOT from a NAND by tying both inputs together, then build AND/OR from NANDs.)

Combinational circuits — no memory

Definition: a combinational circuit's output at any time is a function only of its inputs at that time. It has no internal memory and no feedback; the output follows the input after a few gate delays.

  • General form: n inputs → m outputs.
  • Three equivalent descriptions: a truth table (all 2ⁿ input combinations), a graphical gate diagram, or Boolean equations.

Sum of products (SOP): OR together one product term per row where the output is 1. Product of sums (POS): AND together one sum term per row where the output is 0.

Example: for F = 1 on rows 010, 011, 110:

SOP: F = Ā·B·C̄ + Ā·B·C + A·B·C̄
     simplifies to  F = Ā·B + B·C̄

Simplification matters because fewer gates = cheaper, faster, cooler, and more reliable.

Simplifying: Karnaugh maps and Quine–McCluskey

  • K-map: an array of 2ⁿ squares, ordered 00, 01, 11, 10 so that neighbouring squares differ in exactly one variable. Circle adjacent 1s in groups of 2, 4, 8 …; each group removes the variable that changes. Adjacency wraps around the edges.
  • Don't-care (d) squares are input combinations that never occur; treat each as 0 or 1, whichever makes the group bigger.
  • Quine–McCluskey is the same idea in table form, good for more than 4 variables and easy to program.

A half adder adds two bits (sum and carry out); a full adder adds three (including carry in). Chain them and you get a ripple-carry adder — but the carry must ripple from the least to the most significant bit, so the delay accumulates. Carry lookahead computes the carries directly from the inputs, breaking the dependency chain; that's why a 32-bit adder built from four 8-bit lookahead blocks is much faster than 32 one-bit stages.

Sequential circuits — adding memory

Definition: a sequential circuit's output depends on the current input and the past history of inputs — equivalently, on the current input and the current state. It contains memory elements (flip-flops) and usually feedback, and changes are synchronised by a clock.

  • Combinational: output = f(input) only. "Memoryless."
  • Sequential: output = f(input, state). State updates on a clock edge.
  • They are not rivals: sequential circuits are built from combinational ones plus flip-flops.

The S–R latch

The simplest memory element: two NOR gates cross-coupled — each output feeds the other gate's input. That feedback is what stores a bit.

SRQ (next)Meaning
00Q (unchanged)Hold — remember
010Reset
101Set
11?Invalid — both outputs forced to 0, and the state on release is unpredictable

Why S = R = 1 is forbidden: the two outputs are supposed to be complements, but this input forces both to 0, breaking that invariant. When the inputs return to 0, the cross-coupled gates race and the final state is unpredictable.

Prep answer: turning a clocked S–R into a D flip-flop

Yes. Feed the D input directly to S, and feed D through an inverter to R:

S = D
R = D̄

Why it works: the forbidden row needs S = R = 1, but now S·R = D·D̄ = 0 always (by the identity A·Ā = 0). Exactly one of set/reset is asserted on every clock, so:

  • D = 1 → S = 1, R = 0 → set (Q becomes 1).
  • D = 0 → S = 0, R = 1 → reset (Q becomes 0).

So the output simply copies D at the clock edge. The invalid state is unreachable, and two inputs collapse into one. That is why it is called a data flip-flop (it stores one bit of data) and a delay flip-flop (it delays the input by one clock).

Adding the clock: the clocked S–R version puts two AND gates in front of the latch so S and R only reach it while the clock is high. That makes the circuit synchronous — changes happen at defined times, not whenever an input wiggles.

J–K, registers, counters

  • J–K flip-flop: like S–R, but all four input combinations are valid; J = K = 1 toggles the output. (No separate T flip-flop is needed — toggle is just J = K = 1.)
  • Register: several D flip-flops sharing a clock, so a whole word is read/written at once. A load signal gates when new data is accepted. A shift register moves data one position per clock, which is how serial I/O works.
  • Counter: a register that increments by 1 (modulo 2ⁿ). An asynchronous (ripple) counter lets each stage trigger the next, so the delay ripples through; a synchronous counter clocks all stages together and is much faster — that's the kind used in a CPU's program counter.

Programmable logic

  • PLD (programmable logic device): a chip the user configures.
  • PLA: a programmable AND plane followed by a programmable OR plane. Because every Boolean function can be written as a sum of products, a PLA can implement any truth table by "connecting" the right intersections — that's the regular structure behind the exercise.
  • PAL: programmable AND plane, fixed OR plane.
  • CPLD: several SPLD-like blocks on one chip.
  • FPGA: a large array of configurable logic blocks plus programmable interconnect. A typical logic block is a lookup table (LUT) — a tiny memory that stores the truth table (a 16-bit LUT gives 4 inputs) — plus a flip-flop and a mux to choose combinational or registered output. "Programming" an FPGA mostly means downloading truth tables into LUTs.
  • The economic driver: custom chips are expensive to design and fabricate; a programmable chip gives you most of the speed with none of the non-recurring cost, and you can change the design after shipping.

Traps and memory hooks

  • "Combinational" = no memory. If the answer depends on what happened before, it's sequential — no exceptions.
  • A ROM is combinational even though it is called memory: the output depends only on the address you present.
  • S = R = 1 is not "both set" — it's an invalid, unstable condition. Any answer that says "sets and resets at once" is wrong.
  • K-map order is 00, 01, 11, 10 — a single bit changes between neighbours. Writing binary order 00, 01, 10, 11 breaks adjacency.
  • Ripple carry is slow by construction; lookahead is the fix. If a question asks why adders are slow, this is the answer.
  • NAND and NOR are universal. Any circuit can be built from either one alone.

If you remember only five things

  1. Boolean algebra: AND/OR/NOT, identities, DeMorgan.
  2. Combinational = output depends only on current input; sequential = output also depends on state (memory).
  3. S–R latch stores a bit but forbids S = R = 1; a D flip-flop removes that by wiring S = D and R = D̄.
  4. Mux selects, decoder enables one of 2ⁿ outputs, ROM is a truth table, adders chain with carries.
  5. PLA = programmable AND + OR planes (SOP in hardware); FPGA = LUTs + flip-flops + interconnect.

Chapter 19 — Control Unit Operation

The big idea in one paragraph

The control unit is the conductor of the orchestra. It reads the instruction, works out which tiny steps are needed, and then switches the right control signals on and off at the right clock ticks. Those tiny steps are micro-operations — "copy PC to MAR", "add 1 to PC", "move MBR to IR". Every instruction you write is executed as a sequence of micro-operations. The chapter then asks the engineering question: how do you build a machine that produces those sequences? Answer: either hardwire the logic (fast, inflexible) or microprogram it (flexible, slower).

Micro-operations

  • A micro-operation is one atomic step of a processor: a simple transfer or arithmetic action involving registers (MAR ← PC, PC ← PC + 1, R1 ← R1 + R2).
  • "Micro" means each step does very little — but together they do everything.
  • The hierarchy is important:
program  →  instruction cycle  →  subcycles  →  micro-operations
             (one per instruction)  (fetch / indirect / execute / interrupt)
  • A program is a sequence of instructions; each instruction runs through an instruction cycle made of subcycles; each subcycle is one or more micro-operations.
  • Micro-operations come in only four kinds:
  1. Register-to-register transfer.
  2. Register to external interface (e.g. register → system bus).
  3. External interface to register (e.g. bus → register).
  4. Arithmetic/logic operation, using registers for both input and output.

Instructions vs micro-operations (prep-work question)

The expected answer: a micro-operation is a basic operation performed during one clock pulse. An instruction consists of a sequence of micro-operations, and the particular sequence depends on the instruction (its opcode and addressing mode).

More precisely, the relationship is one-to-many:

  • One instruction expands into a fixed number of micro-operations only for the fixed cycles (fetch, indirect, interrupt). In the execute cycle, the sequence depends on the opcode, so each instruction has its own.
  • The control unit's job is exactly this translation: instruction in, timed control signals out.
  • This is why the chapter can say the processor's behaviour is defined as "the performance of a sequence of micro-operations" — that description is complete, and it is what the hardware must implement.

The four cycles

1. Fetch cycle (three steps, four micro-operations)

Registers: MAR (address), MBR (data), PC (next address), IR (instruction).

t1:  MAR ← PC
t2:  MBR ← Memory          (memory read at the MAR address)
     PC  ← PC + 1           (independent of the read — done at the same time)
t3:  IR  ← MBR

Why the timing matters: the read and the increment are independent, so they happen simultaneously in one clock pulse. And MBR → IR frees the MBR for the next cycle (an indirect cycle needs it).

2. Indirect cycle (only if the instruction uses an indirect address)

t1:  MAR ← IR(address)
t2:  MBR ← Memory
t3:  IR(address) ← MBR(address)

The instruction's address field pointed to a location that holds the operand's address. After this cycle, the IR holds a direct address, so the execute cycle doesn't need to know the difference.

3. Execute cycle (one sequence per opcode)

Example, ADD R1, X (add the contents of memory location X to R1):

t1:  MAR ← IR(address)
t2:  MBR ← Memory
t3:  R1  ← R1 + MBR

Real instructions need more micro-operations (extracting the register reference from the IR, staging ALU inputs and outputs). Instruction decoding is exactly the control unit choosing this sequence from the opcode.

4. Interrupt cycle

At the end of execute, the processor tests for an enabled interrupt. If one is pending:

t1:  MBR ← PC                    (save the return address)
t2:  MAR ← Save_Address
     PC  ← Routine_Address        (jump to the handler)
t3:  Memory ← MBR                (store the old PC)

Then the next instruction cycle starts in the handler.

Deciding which cycle comes next: the ICC

A 2-bit instruction cycle code (ICC) holds the state:

ICCNext cycle
00Fetch
01Indirect
10Execute
11Interrupt

Rules: indirect is always followed by execute; interrupt is always followed by fetch; after fetch and execute, the next state depends on the system state (is an interrupt pending? does the instruction use an indirect address?). This little state machine is the skeleton of the control unit.

What the control unit is and does

Two basic tasks:

  1. Sequencing — step the processor through micro-operations in the right order, based on the program.
  2. Execution — cause each micro-operation actually to happen.

Inputs (Figure 19.4):

  • Clock — one micro-operation (or one set of simultaneous ones) per clock pulse.
  • Instruction register — the opcode and addressing mode select the execute-cycle sequence.
  • Flags — processor status and the outcome of previous ALU operations (e.g. a zero flag decides whether ISZ increments the PC).
  • Control signals from the control bus — e.g. an interrupt request, or a memory-ready signal.

Outputs:

  • Control signals inside the processor (register-to-register moves, ALU function selection, data-path gates).
  • Control signals to the control bus (memory read/write, I/O commands).

All of them end up as binary inputs to logic gates: open this gate, select that ALU function.

A useful limit to remember: the control unit never sees the data — only the instruction and the nature of the result (sign, zero, overflow), via the flags. That's why flags exist.

Hardwired implementation (prep-work question)

Answer: in a hardwired implementation, the control unit is essentially a combinatorial circuit. Its input logic signals are transformed into a set of output logic signals, which are the control signals.

Unpacked:

  • It is built from logic gates, not from a stored program. The mapping from inputs to control signals is fixed in the wiring.
  • Its inputs are the instruction register (opcode + addressing mode), the flags, the clock, and control-bus signals.
  • Two items need decoding before they are useful:
  • The IR goes through a decoder: n inputs produce 2ⁿ outputs, exactly one of which is active for each input pattern. (A 4-input decoder has 16 outputs.) Real decoders are more complex because instruction lengths vary.
  • The clock goes through a counter that produces time steps T1, T2, …, and is reset at the start of each instruction cycle.
  • Then a block of logic combines (decoded instruction) × (time step) × (flags) into each control signal.

Consequences:

  • Fast — signals propagate through gates, no memory access.
  • Inflexible — adding a new instruction means redesigning the logic. Hard to design and test, and errors are hard to fix.
  • It needs extra state to know which cycle it is in: that's the two phase flags from Exercise 19.2. Without them, the same opcode in the fetch phase and in the execute phase would generate the same signals.

Microprogrammed implementation

The alternative: instead of wiring the control signals, store them as words in a control memory, and have the control unit fetch and execute those words just like a tiny program.

  • The term microprogram was coined by M. V. Wilkes in the early 1950s. It became practical only with fast, cheap control memory.
  • IBM System/360 (April 1964) made it famous: all but the largest models were microprogrammed.
  • Vocabulary: one line = one microinstruction; a sequence = a microprogram; the whole thing is firmware (between hardware and software — easier to design than hardware, harder to write than software).

The organisation (Figures 19.13–19.15):

  • Control memory holds the microinstructions.
  • The control address register holds the address of the next microinstruction.
  • The word is read into the control buffer register; its left part is the control signals (reading it executes it), and its right part is next-address information.
  • A sequencing unit decides the next address: increment (next microinstruction), jump to a routine, or jump to the routine for the opcode in the IR.
  • One microinstruction completes in one clock pulse: issue the read, latch the word, apply the control signals, compute the next address.

Trade-off summary:

  • Microprogrammed: simpler to design and cheaper to build, easy to change (rewrite the microprogram) — but slower than hardwired, because every control signal costs a control-memory access.
  • Hardwired: faster, but rigid and expensive to design.
  • Historically: CISC processors used microprogramming (complex instruction sets benefit from the flexibility); RISC processors usually use hardwired control (simple, regular instructions don't need it).

Exercise 19.1 — subtraction with an ALU that can only add and complement

Your ALU can add its two input registers and can complement either input register, but it cannot subtract. Numbers are in two's complement. List the micro-operations your control unit must perform to cause a subtraction.

The trick is to compute A − B using only complement and add. In two's complement, −B = B̄ + 1, but there is no increment available — so use the algebraic identity:

A − B  =  complement( B + complement(A) )

Why? Because complement(X) = −X − 1, so complement(B + Ā) = −(B + Ā) − 1 = −B − Ā − 1 = −B + A (since Ā = −A − 1, so −Ā − 1 = A).

Micro-operations:

t1:  A ← complement(A)
t2:  A ← A + B
t3:  A ← complement(A)

Check with 4-bit numbers: A = 0101 (5), B = 0011 (3).

t1: A = 1010 (-6)
t2: A = 1010 + 0011 = 1101 (-3)
t3: A = 0010 = 2   ✔ (5 - 3)

The same trick works for any pair. Notice how the control unit is just issuing three register-transfer steps — that's what "control" means.

Exercise 19.2 — why the phase flags?

A simple processor has four phases: fetch, indirect, execute, interrupt. Two 1-bit flags designate the current phase in a hardwired implementation.

(a) Why are these flags needed? A hardwired control unit is a combinatorial circuit: its outputs depend only on its inputs (IR, flags, clock, bus signals). But the same opcode means different things in different phases — during fetch, the IR's contents must not be interpreted as an execute operation. The two flags store the current phase, so the logic can select the correct control-signal pattern. Without that state, the machine could not tell "I am fetching" from "I am executing", and the control signals would be wrong.

(b) Why are they not needed in a microprogrammed unit? The phase is encoded in the control memory address — the microinstruction currently executing is the state. Advancing (or jumping) to the next microinstruction updates the phase automatically, so no separate flags are required. This is a general lesson: microprogramming replaces explicit state logic with stored sequence.

Traps and memory hooks

  • A micro-operation is not an instruction. One instruction = many micro-operations.
  • Fetch and execute always happen; indirect and interrupt happen only when needed.
  • The ICC is 2 bits: 00 fetch, 01 indirect, 10 execute, 11 interrupt.
  • Hardwired = combinational circuit = fast but rigid; microprogrammed = stored microinstructions = flexible but slower. Match the phrase "essentially a combinatorial circuit" with hardwired — that's the exam's tell.
  • Flags carry information the control unit cannot see in the data (zero, sign, overflow).
  • Microprograms live in control memory, which is not the main memory the program uses.

If you remember only five things

  1. A micro-operation is one atomic register-transfer or ALU step, done in one clock pulse; an instruction is a sequence of them.
  2. Fetch = MAR←PC, MBR←Memory & PC←PC+1, IR←MBR.
  3. The control unit sequences micro-operations and executes them by raising control signals; its inputs are clock, IR, flags, and control bus.
  4. Hardwired control = a combinatorial circuit of gates, decoded IR + T-step counter — fast, inflexible.
  5. Microprogrammed control = microinstructions in control memory with a sequencing unit — flexible, slower.

Chapter 1

1. Explain Moore's Law.

In 1965, Gordon Moore observed that the number of transistors that could be put on a single chip was doubling every year, and he correctly predicted that the pace would continue into the near future. (The pace was later revised in the 1970s to a doubling about every 18 months, and that is the version the industry used for decades.) It held because the industry funded each generation of fabrication, and it drove down the cost of logic and memory, raised speed, reduced size and power, and reduced the number of inter-chip connections.

Keywords: 1965 · Gordon Moore · transistors per chip · doubling every year (~18 months) · cost/speed/size/power consequences.

2. List and briefly describe the main structural components of a computer.

Central processing unit (CPU): controls the operation of the computer and performs its data-processing functions; often called the processor. Main memory: stores data. I/O: moves data between the computer and its external environment. System interconnection: the mechanism that provides communication among the CPU, main memory, and I/O — typically a system bus, a set of conducting wires to which all components attach.

Keywords: CPU · main memory · I/O · system interconnection/bus · (inside the CPU: control unit, ALU, registers, CPU interconnection).

Chapter 3

1. List and briefly define two approaches to dealing with multiple system interrupts.

(1) Disable interrupts while an interrupt is being processed. New requests are ignored but remain pending and are checked when interrupts are re-enabled. Handlers run strictly sequentially. It is simple, but it ignores priority: a slow handler can delay a time-critical device long enough to lose data.

(2) Define interrupt priorities. A higher-priority interrupt is allowed to interrupt (preempt) a lower-priority handler, so handlers nest. Urgent devices get service first, at the cost of more complex control.

Keywords: disable interrupts / pending / sequential · priorities / preemption / nesting.

2. What general categories of functions are specified by computer instructions?

Processor–memory: data transferred from processor to memory or memory to processor. Processor–I/O: data transferred to or from a peripheral, via an I/O module. Data processing: the processor performs an arithmetic or logic operation on data. Control: the instruction specifies that the sequence of execution be altered (a branch/jump).

Keywords: processor–memory · processor–I/O · data processing · control.

Chapter 7

1. How is redundancy achieved in a striped RAID system?

Striping alone provides no redundancy — it only spreads data for speed and capacity. Redundancy is added by storing derived information in redundant capacity: RAID 1 duplicates every strip on a second disk (mirroring); RAID 2 uses Hamming error-correcting codes across corresponding bits on multiple check disks; RAID 3, 4 and 5 use parity (one check disk; RAID 5 distributes the parity blocks across all disks); RAID 6 uses two independent parity blocks on different disks. On failure, the lost data is reconstructed from the mirror or from the parity, and the array runs in reduced mode until the disk is replaced and rebuilt.

Keywords: mirroring (RAID 1) · ECC/Hamming (RAID 2) · parity (3/4/5/6) · distributed parity (5) · dual parity (6) · reconstruct/reduced mode.

2. What are the advantages of using a glass substrate for a magnetic disk?

(1) More uniform magnetic film surface → better reliability. (2) Significantly fewer surface defects → fewer read/write errors. (3) Allows lower fly heights — the head can fly closer to the surface, so narrower tracks and higher areal density. (4) Better stiffness → less disk dynamics (vibration/wobble). (5) Greater ability to withstand shock and damage.

Keywords: uniformity · fewer defects · lower fly height · stiffness · shock resistance.

Chapter 10

1. What is the BCD representation of numbers?

Binary-coded decimal: each decimal digit is encoded in its own 4-bit binary code. For example, 1278₁₀ is encoded as 0001 0010 0111 1000 — one nibble per decimal digit, not the binary value of the whole number. It is convenient for decimal displays and calculators because no binary↔decimal conversion is needed, but it wastes 6 of the 16 codes and needs a +6 correction when a nibble exceeds 9 during addition.

Keywords: each decimal digit · 4 bits · example · display-friendly · wasteful/invalid codes.

2. Why do most assembly code listings adopt hexadecimal numbers instead of binary numbers?

(1) More compact — one hex digit encodes four bits, so a 32-bit instruction is 8 characters instead of 32. (2) Data widths are multiples of 4 bits, so hex always fits exactly (no ragged edge). (3) Conversion is trivial — just group bits in fours; no arithmetic, no loss of precision. (4) The width is fixed: 3₁₀ is 03₁₆ and 128₁₀ is 80₁₆, both two digits, so a listing stays aligned and legible for humans and simple compilers, unlike decimal where widths vary from 1 to 3 digits. Hex is also a concise notation for any bit pattern, not just numbers.

Keywords: compact · 4-bit grouping · trivial conversion · no loss of precision · fixed width/alignment.

Chapter 11

1. What is the sign extension rule for two's complement numbers?

When widening a two's complement number to more bits, copy the sign bit into every new position on the left — zeros for a positive number, ones for a negative number. Example: +18 = 0001 0010 becomes 0000 0000 0001 0010; −18 = 1110 1110 becomes 1111 1111 1110 1110. Padding with zeros instead would change a negative number's value, because the old sign bit's weight −2⁷ would be lost; filling with copies of the sign bit preserves the value.

Keywords: replicate/copy the sign bit · zeros if positive, ones if negative · example · value preserved.

2. Give a reason for the use of guard bits.

Guard bits are extra bits at the right end of the significand (padding with zeros). They retain low-order bits that would otherwise be shifted out during alignment, so the result can be rounded correctly instead of being truncated early. Without them, subtracting two nearly equal numbers can lose the least significant bit and give an answer that is wrong by a factor of 2 (or 16 in radix-16 formats).

Keywords: extra low-order bits · alignment/shift · avoid losing least significant bits · correct rounding · factor-of-2 error.

Chapter 12

1. What is the difference between a combinatorial circuit and a sequential circuit?

A combinational circuit has no internal memory: its output depends exclusively on its present input (after a small gate delay). A sequential circuit contains memory (flip-flops), so its output depends on the present input and the internal state (the past history); for the same input there may be more than one possible output. Sequential circuits are built from combinational logic plus memory elements, and their state changes are usually synchronised by a clock.

Keywords: no memory vs internal state/memory · output = f(input) vs f(input, state) · feedback/clock.

2. Is it possible to transform a clocked S–R flip-flop into a D flip-flop, and if so, how?

Yes. Connect the data input D to S, and D through an inverter to R: S = D, R = D̄. Now S·R = D·D̄ = 0 always, so the invalid S = R = 1 condition can never occur, and exactly one of set/reset is asserted at each clock. If D = 1 the flip-flop sets; if D = 0 it resets — so the output simply follows D at the clock edge (hence "data" and "delay" flip-flop).

Keywords: S = D · R = D̄ (inverter) · S·R = 0 so invalid state impossible · output follows D.

Chapter 19

1. What is the relationship between instructions and micro-operations?

A micro-operation is one basic, atomic operation performed during one clock pulse (e.g. MAR ← PC). An instruction is executed as a sequence of micro-operations: the fixed cycles (fetch, indirect, interrupt) have predefined sequences, while the execute cycle's sequence depends on the opcode and addressing mode. So one instruction maps to many micro-operations, and the control unit's job is to generate that sequence and its control signals.

Keywords: micro-op = one clock pulse · instruction = sequence of micro-ops · opcode-dependent execute · control unit sequences them.

2. Briefly explain what is meant by a hardwired implementation of a control unit.

The control unit is built as logic gates — essentially a combinatorial circuit — whose input logic signals (decoded instruction register, flags, clock/time-step counter, control-bus signals) are transformed into a fixed set of output control signals. There is no stored program: the instruction-to-control-signal mapping is fixed in the wiring. It is fast but inflexible — adding an instruction means redesigning the logic — and it needs state (phase flags) to know which cycle it is in.

Keywords: combinatorial circuit · input logic signals → output control signals · decoded IR + clock counter · fast but inflexible.

Exercise 1.2 — "is the 2.4 GHz Pentium faster than the 1.2 GHz Mac?"

No, Billy Bob is not correct, and "GHz" alone cannot answer the question. Clock speed says how many cycles per second, not how much work per cycle (CPI) or how efficient the rest of the system is. Two machines can have the same clock and very different performance because of:

  • differences in instruction sets (CISC vs RISC, different work per instruction),
  • organization: cache sizes and speeds, pipeline depth, superscalar width,
  • memory and bus speeds (a fast CPU starved by slow memory is not fast),
  • and the task itself (integer, floating point, graphics, I/O).

What you should tell the customer: compare the systems by running benchmarks for the tasks they actually care about (office applications, floating-point work, graphics, games) and compare time to complete those tasks. The slides note that Apple claimed the G4 was comparable or better than a higher-clock Pentium on many benchmarks — which is exactly the point.

Model answer in one sentence: clock speed is only one factor; performance is determined by the whole system and the instruction mix, so you must benchmark.

Exercise 3.1 — bus throughput: wider bus or faster clock?

A 32-bit microprocessor with a 16-bit external data bus, an 8 MHz clock, and a bus cycle of 4 clock cycles. (a) Maximum data transfer rate in bytes/s? (b) To improve performance, is it better to widen the bus to 32 bits or to double the clock?

(a)

bus cycle = 4 clocks ÷ 8,000,000 clocks/s = 0.5 µs
bytes per cycle = 16 bits ÷ 8 = 2 bytes
rate = 2 bytes ÷ 0.5 µs = 4,000,000 bytes/s = 4 MB/s

(b) Both give the same throughput — 8 MB/s — so the choice is not decided by raw bandwidth:

  • Double the clock → bus cycle = 0.25 µs → 2 bytes / 0.25 µs = 8 MB/s.
  • Widen the bus to 32 bits → 4 bytes / 0.5 µs = 8 MB/s.

Which is "better"? It depends on cost and constraints, and you should say so:

  • Widening the bus means more pins and traces and a wider memory interface, but it also removes the mismatch between a 32-bit processor and a 16-bit bus — the processor currently needs two bus cycles per 32-bit word.
  • Doubling the clock requires faster memory and peripherals (and may hit signal-integrity limits); everything on the bus must keep up.

Assumptions to state: one transfer every bus cycle, no wait states, and the bus can sustain the clock (i.e. memory is fast enough). The hint in the question tells you the key step: work out how many bytes are transferred per bus cycle.

Exercise 3.2 — the VAX SBI: why does priority 16 have no TR line?

The SBI is a distributed, synchronous arbitration scheme. Each device has a unique priority and a unique transfer request (TR) line. There are 16 TR lines (TR0–TR15) with TR0 highest priority. A device reserves a future time slot by asserting its TR line during the current slot; at the end of the slot, every device with a pending reservation examines the TR lines, and the highest-priority one gets the next slot. Up to 17 devices can attach, but the priority-16 device has no TR line. Why?

Answer: it doesn't need one. It is the lowest-priority device, so it can never win a reservation while any other device is requesting — every TR line outranks it. It therefore gains the bus only when the bus is idle (no TR line asserted), at which point no reservation is needed: idle means nobody is competing, so it simply uses the next slot. Giving it a 17th TR line would add a wire and a priority bit for a device whose reservation could never succeed.

The concept being tested: arbitration is a competition, and a fixed-priority scheme only needs lines for the contestants that can actually win. This is the same "priority vs arrival order" idea as interrupt priorities in Chapter 3.

Exercise 11.1 — the bit-copying trick

Start at the least significant bit. Copy all 0s until the first 1, copy that 1 too, then complement every bit after that. What is the result?

The result is the two's complement negation of the number (i.e. −x).

Why: the standard negation is "complement all bits, then add 1". Complementing all bits turns every trailing 0 into a 1; adding 1 flips those back to 0 up to and including the first original 1, and leaves the higher bits complemented. The trick describes exactly that final pattern, without ever doing the addition.

Example: x = 0110 1000 (104).

trailing zeros (000) copied → 000
first 1 copied              → 1000
complement the rest (0110)  → 1001
result: 1001 1000 = -104

Check: 0110 1000 + 1001 1000 = 1 0000 0000 → the carry is discarded, giving 0 ✔

Why it's useful: it is how a hardware incrementer can be fused into the complement path, and it explains why the "first 1" is special.

Exercise 12.1 — build XOR from AND, OR, NOT

Truth table: XOR is 1 when exactly one input is 1 — rows 01 and 10.

Two equivalent standard forms:

XOR = Ā·B + A·B̄            (sum of products: one term per 1-row)
XOR = (A + B) · (Ā + B̄)     (product of sums: one term per 0-row)

Circuit for the first form: two NOT gates (for Ā and B̄), two AND gates (ĀB and AB̄), one OR gate to combine them. Five gates.

Check: A = 0, B = 1 → 1·1 + 0·0 = 1 ✔; A = 1, B = 1 → 0 + 0 = 0 ✔.

NAND-only version (bonus): XOR = NAND( NAND(A, NAND(A,B)), NAND(B, NAND(A,B)) ) — four NAND gates. This is how XOR is actually built, because NAND is the cheap universal gate.

Exercise 12.2 — a PLA for four outputs

Inputs C, B, A; outputs O₀…O₃:

O₀ = ĀB̄C + AB̄ + ABC̄
O₁ = ĀB̄C + ABC̄
O₂ = C
O₃ = AB̄ + ABC̄

Step 1 — list the required product terms. Reading across the four expressions, only three distinct products appear:

P1 = Ā·B̄·C
P2 = A·B̄
P3 = A·B·C̄

(Plus C on its own for O₂, which can come straight from the C input line.)

Step 2 — the AND plane has 6 literal lines (C, C̄, B, B̄, A, Ā) and 3 AND gates, one per product term, with connections at the literals present in that term.

Step 3 — the OR plane has 4 OR gates:

O₀ = P1 + P2 + P3
O₁ = P1 + P3
O₂ = C
O₃ = P2 + P3

Step 4 — the structure is: inputs → NOT gates for the literals → programmable AND array (3 product lines) → programmable OR array (4 output lines). Each intersection is either connected or not — that is the "programming".

Why a PLA is the natural answer: every output is in sum-of-products form, and a PLA is literally a hardware SOP evaluator. The exercise is testing whether you can see that shared product terms save hardware — P1, P2, P3 are each reused by two or more outputs.

The I/O module

An I/O module is the go-between connecting the system bus to a peripheral. It carries three kinds of signal — control, status, and data — and performs five jobs:

  1. Control and timing — coordinate the flow of data between the processor and the device.
  2. Processor communication — command decoding, data transfer, status reporting (BUSY/READY), address recognition.
  3. Device communication — the device-specific signalling.
  4. Data buffering — absorb the speed mismatch between the device and memory/processor.
  5. Error detection — mechanical/electrical faults and transmission errors (e.g. parity).

Devices fall into three classes: human readable (screens, printers), machine readable (disks, sensors, actuators), and communication (remote terminals, other computers).

A module with a high-level interface (it runs its own little programs) is an I/O channel or I/O processor; a primitive one that needs detailed control is an I/O controller.

  • Memory-mapped I/O: the device's registers appear as memory addresses, so ordinary load/store instructions work — but they consume the address space.
  • Isolated I/O: a separate I/O address space with special I/O instructions and select lines.
  • DMA cycle stealing: the DMA controller takes a bus cycle now and then (a "cycle steal"); the processor merely pauses, it does not save context, because it is not an interrupt.

Identifying the interrupting device

Four classic techniques, in order of sophistication:

  1. Multiple interrupt lines — simplest, but impractical beyond a handful, so devices share lines.
  2. Software poll — the processor asks each device in turn; simple but slow.
  3. Daisy chain (hardware poll) — the acknowledge ripples through the devices; the requesting device returns a vector pointing at its handler.
  4. Bus arbitration — the device must first win the bus, then places its vector on the data lines.

A vectored interrupt gives the processor the handler's address directly, so it doesn't have to guess.

Channels and modern standards

  • An I/O channel is a processor in its own right, executing channel programs from memory. A selector channel serves one high-speed device at a time; a multiplexor channel serves several (byte-multiplexor interleaves characters, block-multiplexor interleaves blocks).
  • Standards worth recognising: USB (1.5/12 Mbps → 480 Mbps → 5/10 Gbps), FireWire, SCSI, Thunderbolt, InfiniBand, SATA, Ethernet (10 Mbps → 100 Mbps → 1/10/40/100 Gbps), Wi-Fi.
  • DCA/DDIO exist because DMA can't keep up with 10–100 Gbps: the I/O device writes into the last-level cache instead of main memory.

If you only remember one thing: I/O is about buffering, addressing, and not making the processor wait — which is exactly what DMA and interrupts are for.
